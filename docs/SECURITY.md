# Local processing and boundaries

The application performs no outbound HTTP requests and uses no remote scripts, fonts, telemetry or service worker. It is a local application, not a deployed upload service. Its web server binds only to `127.0.0.1`, uses a random 256-bit capability URL, checks the exact Host and Origin, rejects cross-site fetches, and publishes a restrictive CSP and no-referrer policy. Do not share or publish that URL. The server serves only fixed asset routes and validated job-ID/side-number routes. User filenames are display-only and HTML-escaped in reports; fixed internal filenames prevent path traversal. Downloads use a fixed attachment filename.

HTTP handling is single-threaded to prevent unbounded simultaneous large uploads. Requests require exact JSON content type and a byte-limited body; input files are separately decoded and limited to 16 MiB. There is one analysis worker at a time. Starting another while one is running is rejected. A new accepted job removes the prior result. Generation guards in the UI prevent a late create/poll/demo response from restoring stale output; changing input, DPI or force choices disables export until rerun.

The disposable worker starts a POSIX process group. It parses and renders PDFs only after per-process address-space, CPU, file-size and file-descriptor limits are set. Rendering is sequential. Cancellation and wall timeout kill the group, including its renderer. Cancellation removes temporary inputs immediately; replacing an analysis or stopping the server removes its entire temporary directory. Completed/failed jobs retain local temporary files until replacement or shutdown. Browser memory retains selected bytes until the tab is reloaded or closed. Source PDFs are never modified.

The decoded-content check and pypdf strict parsing are defense in depth, not a general PDF validator. Finite rendering fingerprints cannot certify print identity. A document may contain unusual print semantics not represented in RGB. The app rejects known active/interactive/optional-content/attachment features, including associated files, external streams, output intents, viewer preferences and Type 3 fonts, but is **not an OS security sandbox for hostile PDFs**. Use trusted documents, keep Python dependencies and Poppler patched, and run under an ordinary unprivileged account. Resource limits are per process, not an aggregate memory guarantee. Fontconfig must have a usable cache. Unknown renderer diagnostics, PDF warnings, font-substitution errors and every nonzero renderer exit fail closed. A narrow exception recognizes only complete `Unable to revert mtime: /absolute/path` lines with exit status zero. Fontconfig emits those from its cache UUID/timestamp-maintenance path, rather than PDF interpretation. Every distinct notice is preserved in JSON `environmentNotices` and the visible UI/HTML warnings; it is never silently discarded. Full pixel/geometry and export-rerender checks still apply. [Fontconfig source](https://chromium.googlesource.com/external/fontconfig/+/refs/heads/master/src/fccache.c), [maintainer bug record](https://bugs.debian.org/cgi-bin/bugreport.cgi?bug=909728)

No printer commands, spooler APIs, account integrations or university systems are accessed. Opening the local browser is optional. The HTML packet is script-free and contains no remote assets; JSON/HTML still disclose display filenames, hashes and assembly decisions. Do not upload sensitive PDFs or packets to a public issue or CI log.
